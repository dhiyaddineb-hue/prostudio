## 1. الملخص التنفيذي

بدأ المشروع بهدف إنشاء خط إنتاج احترافي لدبلجة الفيديو إلى العربية مع الحفاظ على هوية المتحدثين، وفصل الحوار عن الموسيقى والمؤثرات، وتحسين الترجمة وفق النوافذ الزمنية، ثم إعادة إخراج الفيديو من دون الصوت الأصلي. خلال مراحل العمل تم اختبار عدة مسارات، وكُشف عدد من العيوب المهمة في التنفيذ السابق، من بينها استخدام VoxCPM Demo بدل VoxCPM2، عدم تمرير المرجع الصوتي بصورة موثوقة، اعتماد صوت واحد عند وجود أكثر من متحدث، مزج غير صحيح للصوت الأصلي، ومزامنة غير مستقرة.

الحالة الحالية تحتوي على خط إنتاج يعمل تقنيًا في GitHub Actions، وتكامل رسمي مع VoxCPM2 المحلي، وطبقة تحسين مخصصة لـ diarization، ولوحة تحكم منشورة عبر GitHub Pages. كما أصبح زر البدء قادرًا على رفع الملف وتشغيل Workflow مباشرة من الصفحة باستخدام Personal Access Token. ومع ذلك، لا ينبغي اعتبار جودة الاستنساخ متعدد المتحدثين نهائية قبل تشغيل اختبار صوتي مستقل لكل متحدث؛ فالنجاح التقني في GitHub لا يساوي تلقائيًا جودة سمعية احترافية.

## 3. التسلسل الزمني للتطوير

### 3.1 الإعداد الأولي وHF_TOKEN

تم فحص مستودع GitHub وتحديد الفرع العامل، ثم إضافة السر `HF_TOKEN` إلى إعدادات المستودع. هذا السر مطلوب للوصول إلى نموذج `pyannote/speaker-diarization-community-1`، مع ضرورة قبول شروط النموذج من حساب Hugging Face نفسه. لا يتم تضمين قيمة السر في الكود أو التقرير.

### 3.2 اختبارات الدبلجة الأولى

تم تشغيل فيديو الاختبار عدة مرات. المسار الأول استخدم VoxCPM Demo عن بعد، ثم ظهرت مشاكل في طوابير Gradio وعدم وضوح اللغة العربية. جرى إلغاء محاولة Edge-TTS بعد أن أوضح المستخدم أنه لا يريد هذا المحرك. كما أزيل مسار Wav2Lip من Workflow الإنتاجي احترامًا لطلب عدم استخدام مزامنة الشفاه المرئية.

### 3.3 اكتشاف مشكلة الترجمة والنطق

أظهرت الاختبارات الأولى أن النص الناتج لم يكن عربيًا بصورة موثوقة، لذلك أضيفت حماية للتحقق من اللغة العربية وإصلاح مسار الترجمة الاحتياطي. بعد ذلك بقيت مشكلات جودة النطق والتوقيت، خصوصًا عند وجود أكثر من متحدث.

### 3.4 فصل الموسيقى والمؤثرات

أضيف مسار Demucs لفصل `vocals` و`no_vocals`، مع الحفاظ على خيار المستخدم في إعادة طبقة الخلفية. كما عولجت أخطاء FFmpeg في خلط الخلفية، ومنع النظام من إعادة الحوار الأصلي عند اختيار إخراج مدبلج.

### 3.5 تطوير التوقيت وتعدد المتحدثين

أضيفت قواعد لمنع تمدد الجملة داخل نافذة المتحدث التالي، واختيار أطول مقطع نظيف كمرجع لكل متحدث، والحفاظ على اسم المتحدث عند تجميع المقاطع. كما أضيفت إزالة للصمت الزائد بعد التوليد وضبط سرعة الصوت دون تغيير طبقته.

### 3.6 إضافة طبقة diarization المخصصة

أضيف الملف:

```text
youtube_auto_dub/diarization_refine.py
```

وتتمثل وظيفته في دمج التحولات المتجاورة للمتحدث نفسه، إزالة التحولات القصيرة الوهمية، معالجة التداخلات، منع احتساب الصوت مرتين، حساب الثقة، وتلخيص مدة كلام كل متحدث. ثم رُبطت هذه الطبقة مع:

```text
youtube_auto_dub/speaker_diarization.py
```

### 3.7 اكتشاف أن VoxCPM لم يكن VoxCPM2

كان اسم العميل داخل المشروع يوحي باستخدام VoxCPM، لكنه كان يتصل فعليًا بـ `openbmb/VoxCPM-Demo` عبر Gradio. هذا سبب جوهري في ضعف الاعتماد على المرجع الصوتي. تم استبدال العميل بالتكامل الرسمي المحلي:

```python
from voxcpm import VoxCPM
VoxCPM.from_pretrained("openbmb/VoxCPM2")
```

وأصبح المرجع يمرر لكل عملية توليد عبر `reference_wav_path`. كما عولج خطأ API أولي سببه تمرير معامل `seed` غير المدعوم.

## 5. الوضع الحالي للمحركات

| المحرك | الوضع الحالي | القرار |
|---|---|---|
| VoxCPM2 | متكامل رسميًا ومحليًا | المسار الافتراضي المطلوب |
| VoxCPM Demo | أزيل من العميل الفعلي | لا يُستخدم |
| XTTS-v2 | موجود كخيار يدوي في Workflow | لا يعمل تلقائيًا |
| Edge-TTS | متاح كخيار تقني قديم | لا يُختار تلقائيًا |
| Seed-VC | متاح كمرحلة لاحقة | لا يُطبق على مزيج متعدد المتحدثين بمرجع واحد |
| Wav2Lip | أزيل من الإنتاج | لا توجد مزامنة شفاه مرئية |

## 6. سبب مشكلة الصوت الواحد

Seed-VC في النسخة الحالية يقبل مرجعًا واحدًا عند تشغيل مرحلة ما بعد التوليد. إذا أُرسل إليه مزيج يحتوي على صوت رجل وصوت امرأة، فسيحاول تحويل المزيج كله إلى هوية المرجع الواحد. لذلك تم وضع قاعدة أمان تمنع Seed-VC من العمل على مزيج diarized متعدد المتحدثين.

المسار الصحيح لتعدد المتحدثين هو تشغيل Seed-VC لكل متحدث على مقاطعه ومرجعه الخاص، ثم إعادة ترتيب المقاطع زمنيًا وخلطها. هذا مختلف جذريًا عن تشغيل Seed-VC مرة واحدة على الفيديو كله، ويحتاج إلى تنفيذ إضافي قبل وصف الميزة بأنها مكتملة.

## 7. لوحة التحكم داخل GitHub

أُنشئت لوحة تحكم باسم **ProStudio Control Room** ونُشرت عبر GitHub Pages. وتشمل الواجهة اختيار اللغة المصدر والهدف، محرك الصوت، الاستنساخ، فصل الخلفية، إعادة الموسيقى والمؤثرات، diarization، نوع الناتج، سجل تشخيص، ومكتبة ملفات المستودع.

الرابط الحي هو:

[فتح ProStudio Control Room](https://dhiyaddineb-hue.github.io/prostudio/)

مصدر الواجهة موجود في:

```text
studio/index.html
docs/index.html
```

وكان سبب ظهور الصفحة القديمة أن GitHub Pages مضبوط على `docs/`، ولذلك نُقلت الواجهة إلى هذا المسار وأعيد النشر بنجاح.

## 8. التشغيل المباشر من الصفحة

أصبح زر **ابدأ الدبلجة تلقائيًا** يقوم بالآتي:

1. يقرأ الملف المختار.
2. يرفعه إلى `inbox/` داخل الفرع.
3. يرسل `workflow_dispatch` إلى GitHub Actions.
4. يمرر اللغة والمحرك وخيارات الفصل وdiarization والخلفية.
5. يعرض حالة العملية في سجل الصفحة.
6. لا يفتح صفحة GitHub Actions.

أضيف أيضًا خيار تذكر التوكن على الجهاز. عند تفعيله يحفظ التوكن في `localStorage`، وعند تعطيله يبقى في الذاكرة أثناء الجلسة فقط. هذا الخيار يحقق طلب الاستخدام مرة واحدة لكنه يحمل مخاطرة أمنية لأن GitHub Pages واجهة عامة.

## 9. متطلبات Personal Access Token

يجب استخدام Fine-grained Personal Access Token محدود بالمستودع `prostudio` فقط، وليس Classic Token واسع الصلاحيات.

| الصلاحية | المستوى |
|---|---|
| Contents | Read and write |
| Actions | Read and write |
| Metadata | Read-only تلقائيًا |

ينبغي عدم إرسال التوكن في المحادثة، وعدم استخدامه على جهاز عام. إذا اختار المستخدم تذكره، فيجب حذف بيانات الموقع أو إلغاء التوكن من GitHub بعد الانتهاء.

## 10. أداة تدقيق المتحدثين

أضيفت الأداة:

```text
speaker_voice_audit.py
```

وWorkflow:

```text
.github/workflows/voice-audit.yml
```

تقوم الأداة باستخراج أطول مرجع للرجل والمرأة، ثم تولد ملف WAV مستقلًا لكل متحدث عبر VoxCPM2 وتنتج `voice_audit_report.json`. هذه الأداة مخصصة لاختبار الهوية الصوتية بتكلفة أقل من إعادة دبلجة الفيديو كاملًا.

تعذر تشغيلها يدويًا من الفرع الحالي لأن GitHub يشترط أحيانًا وجود Workflow في الفرع الافتراضي حتى يتعرف على `workflow_dispatch`. يمكن تشغيلها بعد دمج الملف في الفرع الافتراضي أو تشغيلها من بيئة GitHub مناسبة.

## 11. ما تحقق بنجاح

تحقق نجاحًا من وجود Workflow يعمل على GitHub Actions، وإضافة سر Hugging Face، وفصل Demucs، وتفعيل diarization، وترجمة العربية، وإخراج فيديو بلا الصوت الأصلي، وتثبيت VoxCPM2 الرسمي، ونشر لوحة التحكم، ومنع XTTS من الاختيار التلقائي، وإزالة lip-sync المرئي.

كما تم اختبار ملفات الوسائط الناتجة باستخدام `ffprobe`. أحد نواتج VoxCPM2 كان بمدة تقارب 40.63 ثانية، بدقة 576×720، وبمسار AAC mono عند 24 kHz.

## 12. ما لم يُثبت بعد

لا يمكن اعتبار استنساخ هويتين صوتيتين مستقلتين مثبتًا نهائيًا قبل الاستماع إلى ملفي الرجل والمرأة الناتجين من أداة التدقيق. كما لم يُنفذ بعد Seed-VC على أساس مستقل لكل متحدث ثم إعادة خلط المقاطع؛ الموجود حاليًا هو حماية تمنع الاستخدام الخاطئ له على مزيج متعدد المتحدثين.

كذلك، GitHub Actions ليس بيئة مثالية لتوليد صوت VoxCPM2 بسرعة؛ فقد استغرق التشغيل المحلي على Runner وقتًا طويلًا بسبب استخدام CPU وعدم توفر CUDA مناسب. جودة الفصل تعتمد على جودة المصدر، خصوصًا إذا كان الصوت Mono أو كان الحوار والموسيقى مختلطين بقوة.

## 13. خطة المرحلة التالية

المرحلة التالية الاحترافية يجب أن تنفذ مولدًا زمنيًا مستقلًا لكل متحدث. يبدأ ذلك بإنشاء ملف manifest يحتوي على `speaker_id` ومرجع الصوت ونص المرجع والمقاطع الزمنية. بعد التوليد، يمر كل ملف صوتي إلى Seed-VC بمرجعه الخاص، ثم تستخدم وحدة المزامنة تمديدًا محدودًا للصوت مع منع قص الكلمات. في النهاية تُركب جميع المقاطع في مسار واحد، ثم يضاف stem الخلفية عند طلب المستخدم فقط.

كما ينبغي إضافة فحص جودة آلي قبل قبول الناتج. هذا الفحص يجب أن يقيس عدد المتحدثين في الناتج، نسبة الصمت، التداخل الزمني، مدة كل مقطع، وجود تسرب من الصوت الأصلي، وفروق مستوى الصوت بين المتحدثين. إذا فشل أي شرط، يجب أن يتوقف Workflow ويرفع تقريرًا بدل إنتاج ملف مضلل.

أما لوحة التحكم، فخطوتها التالية هي إضافة polling لحالة Workflow، عرض progress لكل مرحلة، عرض artifact النهائي داخل الصفحة، إضافة زر إلغاء، وعرض تقرير `voice_audit_report.json` بجانب مشغل الصوت.

## 14. الخلاصة

المشروع انتقل من نموذج تجريبي يعتمد على VoxCPM Demo ومسارات غير مستقرة إلى بنية إنتاجية أوضح تعتمد على VoxCPM2 الرسمي، Demucs، PyAnnote، ترجمة واعية بالمدة، ولوحة تحكم منشورة. تم التعامل مع XTTS وفق رغبة المستخدم بحيث لا يعمل إلا باختيار يدوي، وأزيلت مزامنة الشفاه المرئية.

النتيجة الحالية **صالحة كأساس هندسي وتشغيل GitHub**، لكنها ليست بعد ضمانًا لجودة استنساخ متعددة المتحدثين بمستوى استوديو. العنصر الحاسم المتبقي هو تنفيذ Seed-VC لكل متحدث بشكل مستقل، ثم إعادة تركيب المقاطع والتحقق السمعي الآلي قبل تسليم الناتج.
